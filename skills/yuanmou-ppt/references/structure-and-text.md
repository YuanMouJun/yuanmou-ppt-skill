# 结构还原与图形内文字规范（`@yuanmou/pptx-kit`）

创建、复用或修正 PPT 对象前阅读本说明，用于根治「版式像但形状/透明度/字色字重全跑偏」和「底色图形另套透明文本框」这两类高频返工。

## 一、逐项核对总表（严禁靠整页缩略图拍脑袋）

先将参考图按功能区切出 **2× 局部放大图**，再按以下 7 项逐一实测落盘：

| 核对项 | 必须实测与核对的内容 |
| :--- | :--- |
| **整体分区** | 顺序、占比、对齐基准、留白与视觉重心 |
| **原生图形** | 数量、形状、像素边界 `[x, y, w, h]`、圆角半径、填充、边框色与透明度 |
| **结构关系** | 并列、包含、分层、分支、汇聚、循环及前后层叠顺序（`overlapping` / `flush` / `spaced`） |
| **连线与箭头** | 起止对象、端点、方向、箭头端尺寸、折点、箭杆是否渐窄及遮挡顺序 |
| **图片槽位** | 槽位数量、宽高比节奏（等大 vs 错落）、裁切方式、有无外框与截图可读性 |
| **文字属性** | 所属图形、实测墨色（如炭灰 `#333333` vs 品牌红）、字重（`regular` vs `bold`；特粗主标题/大数字优先选用本机可用 Heavy/W6 字重如 `Hiragino Sans GB W6` / `Source Han Sans CN Heavy`）、字号（`pt ≈ h_px × 0.80`）、内边距与换行 |
| **跨对象穿插交点** | 关键边界相对位置：如箭头肩部横线在椭圆上沿红线的上方还是齐平、小圆点圆心是否正好压在椭圆底弧上、粉底标签是否半压在通栏上沿 |
| **视觉效果** | 渐变色标位置/颜色/透明度（`<a:alpha>`）、渐变方向、描边色与柔光叠层 |

## 二、复杂图形与视觉效果精检清单

复杂区域必须先看 **2× 局部大图** 并多点采样（顶部像素、底部像素、描边像素、透底交叉像素、文字最深笔画像素），再用 `@yuanmou/pptx-kit` 原生对象建模：

| 图形类别 | 重绘与 2× 局部复核必须检查的细节 |
| :--- | :--- |
| **圆角倒梯形 / 漏斗层** | 必须调用 `buildRoundedTrapezoidPath()` / `buildRoundedPolygonCommands(points, radius)` 还原平滑圆角与精确上下底收窄斜率，禁止用尖角直线多边形凑合 |
| **纵向渐窄箭头** | 箭身长度、上宽下窄收窄比例、箭头端宽高、颈部位置、渐变强度与透底遮挡顺序 |
| **锥体与半透明分层椭圆** | 侧边曲率、各层宽高递增比例、**顶部高不透明 → 底部低不透明（`rgba(..., 0.96)` → `rgba(..., 0.08)`）的玻璃透底效果**（确保底层箭头可从椭圆下半部透出）、细描边色与内部文字条形（直角矩形 vs 圆角胶囊） |
| **直角括线与树状连接** | 横竖臂各自粗细、长度、转角对齐、端点衔接与渐变方向；双向消隐边线调用 `buildPolylineStrokeCommands()` |
| **渐变与浅色背景带** | 核对每个色标的位置、颜色、透明度与角度，确认白底上的浅色渐变、背景柔光与标题层次在渲染后依然清晰可见 |

## 三、单图形承载底色与富文本铁律

一个标签、标题条、步骤框、圆形节点或带色说明框，**必须由同一个原生 `<p:sp>` 图形保存几何、填充、边框及文字**。

### 正确示例（`@yuanmou/pptx-kit`）

```js
slide.shapes.add({
  name: "核心策略节点",
  geometry: "roundRect",
  position: { left: 80, top: 160, width: 240, height: 64 },
  borderRadius: 8,
  fill: "#B82228",
  line: { fill: "#B82228", width: 1, style: "solid" },
  text: "核心策略节点",
  textStyle: {
    fontFamily: "PingFang SC",
    fontSize: 20,
    bold: true,
    color: "#FFFFFF",
    alignment: "center",
    verticalAlignment: "middle",
    insets: { left: 8, right: 8, top: 4, bottom: 4 },
  },
});
```

标题与说明需要不同字号、颜色、字重时，直接在同一个图形的 `text` 数组中使用多段落/多 `runs` 富文本设置；表格文字直接写入原生单元格 `<a:tbl>`。

### 必须禁止的 5 种反模式构造
1. 先画带色矩形，再在内部叠一个白底、同色底或描边文本框承载同一段文字；
2. 先画底色图形，再覆盖一个透明文本框（视觉接近但移动/缩放立刻错位）；
3. 把底色图形与文字框编组，冒充“文字已属于底色图形”；
4. 为原图本来没有底色的旁注自动套白底小框或多余红框/虚线框；
5. 为硬塞过长文案而擅自改圆角、拉大节点、缩成极小字号或破坏原参考比例。

> 说明：参考图中的大容器（如大卡片/分栏底板）内部可能确实包含多个独立语义的子节点、图表或图片，应保留这些独立对象与层级；但**同一语义节点**的底色、边框与内部标题/说明必须在节点自身 `<p:txBody>` 内排版。

## 四、对象归属检查与双模式渲染核验

1. **双模式流水线（`structure` → `final`）**：
   - 多页任务按**单页独立脚本**推进，每页先以 `structure` 模式仅导出结构与原模板样式草稿；
   - 渲染后同时核对「**全页 50% 半透明叠图**」与「**高细节区 2× 局部放大并排图**」，修正至轮廓、透明度、描边、字色、字重全部吻合后，再切换 `final` 模式锁死样式注入用户图文。
2. **交付前双重复核（原生对象 + 实际渲染均须通过）**：
   - **对象层面**：确认带底色节点由同一 `<p:sp>` 同时持有图形填充与 `<p:txBody>`，排除承载同一内容的内框、覆盖透明文本框与背景文字分离；移动或缩放底色节点时文字须随同一对象变化（不能靠编组冒充）；表格文字须归属原生单元格，图表须内嵌 `.xlsx`；
   - **视觉层面**：通过 `deck_cli.mjs verify --ref-dir` 生成多页高清左右对照 PDF（`qa_compare.pdf`）与 4 页一组高清拼图（`compare_batch_*.jpg`）逐批交付核验。
